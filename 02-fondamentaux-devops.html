Rappel des fondamentaux du DevOps

Poser un vocabulaire commun avant d'y injecter de l'IA : culture, boucle de livraison, pratiques clés et métriques de performance.

🎯 Objectifs du module

  • Rappeler la définition du DevOps et ses piliers culturels (CALMS).

1DevOps : une culture avant d'être des outils

Le DevOps vise à livrer plus vite, plus souvent et plus sûrement de la valeur aux utilisateurs, en faisant tomber le « mur » entre ceux qui développent (Dev) et ceux qui exploitent (Ops).

Le modèle CALMS

C · Culture

Favoriser la collaboration entre l'équipe de développement et l'équipe d'exploitation, sans se rejeter les responsabilités.

A · Automation

Automatiser tout ce qui est répétitif : build, tests, déploiement, infra.

L · Lean

Éliminer les tâches sans valeur ajoutée.

M · Measurement

Mesurer pour décider : métriques de flux, de qualité, d'exploitation.

S · Sharing

Partager connaissances, outils, retours d'expérience entre équipes.

Les étapes en détail

📋 Plan

Découper et prioriser le besoin.

Jira · GitLab Issues

💻 Code

Écrire et relire le code via des merge requests.

Git · GitLab/GitHub

🔨 Build

Produire un artefact versionné et reproductible.

Docker · Maven · npm

🧪 Test

Vérifier le fonctionnel et la sécurité automatiquement.

pytest · JUnit · Trivy

📦 Release

Versionner et publier l'artefact.

ECR · Harbor · Git tags

🚀 Deploy

Déployer de façon déclarative et réversible.

Kubernetes · Argo CD · Terraform

⚙️ Operate

Exploiter : supervision et runbooks.

kubectl · PagerDuty

🔭 Monitor

Observer et détecter les problèmes.

Prometheus · Grafana · Loki · EFK

3Les pratiques clés

🔁 Intégration continue (CI)

Chaque commit déclenche build + tests + analyses. Les problèmes sont détectés tôt et à petite échelle.

🚚 Livraison / déploiement continu (CD)

Delivery : toujours prêt à livrer (déclenchement manuel). Deployment : chaque changement validé part en production automatiquement.

🏗️ Infrastructure as Code (IaC)

L'infrastructure est décrite dans du code versionné (Terraform/OpenTofu, Ansible) : reproductible, relisable, testable.

🌀 GitOps

Git est la source de vérité de l'état désiré ; un agent (Argo CD, Flux) réconcilie en continu le cluster avec Git. Rollback = git revert.

📦 Conteneurs & orchestration

Docker pour empaqueter, Kubernetes pour orchestrer : déploiements déclaratifs, auto‑réparation, mise à l'échelle.

🔭 Observabilité

Métriques, logs, traces (OpenTelemetry) pour comprendre l'état interne d'un système à partir de ses sorties.

🛡️ DevSecOps / shift‑left

La sécurité intégrée dès le début : scan de secrets, SAST, scan d'images et d'IaC, politique de dépendances.

🧱 Platform engineering

Une équipe plateforme fournit des « chemins balisés » (golden paths) en libre‑service aux équipes produit.

✅ Ce qu'il faut retenir

  • DevOps est une culture avant d'être des outils : CALMS (Culture, Automatisation, Lean, Mesure, Partage) et la levée des silos dev/ops.
  • Les pratiques clés transforment la culture en réalité : CI/CD, IaC, GitOps (Git comme source de vérité), observabilité, DevSecOps (shift-left), platform engineering.
  • Les métriques DORA mesurent vitesse et stabilité : fréquence de déploiement, délai de livraison, taux d'échec des changements, temps de restauration.
  • Ce sont les fondamentaux que l'IA viendra enrichir au module suivant : sans eux, pas de collaboration IA fiable.
